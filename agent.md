# Agent context — isodepth-statistical-testing

Non-obvious, reusable notes for working in this repo.

## Covariate model (decoder-only) — closed-form for linear/quadratic
- The covariate model uses a **fixed** latent (midline depth `z-score(|x - median(x)|)`, or a per-cell obs column z-scored) and only fits the decoder.
- For `decoder` in {`linear`, `quadratic`} the decoder is affine in fixed latent features, so the covariate decoder is fit by **closed-form OLS** instead of NN training. Only `decoder="nn"` still trains iteratively.
- Implementation:
  - `data/transforms.py::midline_latent(S)` — numpy midline latent; matches `MidlineLatentSingle` (uses lower-median for even N to match `torch.median`).
  - `methods/trainers/isodepth.py::fit_closed_form_decoder(latent, A, decoder_type)` — OLS, design `[z,1]` (linear) / `[z,z^2,1]` (quadratic); `covariate_decoder_is_closed_form(config)` predicate.
  - Branch lives in `methods/permutation.py::_train_covariate_artifacts` (single chokepoint for all 4 covariate call sites: main, full-retraining, celltype-together, celltype-separate).
- Artifacts produced must keep shapes: `pred_true_covariate` (N,G), `true_isodepth_covariate` (N,).
- **Poisson parametric decoder uses post-hoc IRLS refit everywhere** (`poisson_parametric_decoder_uses_irls` in `methods/trainers/isodepth.py`): when `metric=nll_poisson_mse` and `decoder` in {`linear`, `quadratic`}, the encoder is still trained with GD (rerun selection unchanged), but `_finalize_batched_parallel_training` / `_finalize_celltype_parallel_training` replace the GD decoder with `fit_poisson_glm_irls` on the learned latent before computing `stat_true`, each `stat_perm`, and stored `pred_*`. Covariate, true, and null slots therefore share the same Poisson-GLM decoder objective. `decoder="nn"` is unchanged (full GD). CV: IRLS fits on `loss_mask` cells, predicts/metrics on `metric_loss_mask` when set (`predict_latent` in `fit_poisson_glm_irls`).
- **Poisson covariate (linear/quadratic) is fit by IRLS, NOT gradient descent** (`fit_poisson_glm_irls`; routed via `poisson_parametric_decoder_uses_irls` in `_train_covariate_artifacts`). It's the count-data analog of `fit_closed_form_decoder`: each gene is an independent Poisson GLM (log link, per-cell exposure offset `log(sf_i)`, `sf` = `poisson_size_factors_np` or row sums), `λ_ig = b_g + Σ w·φ(z)` with `φ=[z]`/`[z,z²]`. Returns **log-rate** `λ` (offset applied later by `compute_metric`); `pred_true_covariate` stays log-rate (separate-mode plots convert via `sf*exp(λ)`). **Why this exists**: the old Adam-GD covariate path *diverged* on small/sparse cell-type subsets — the fixed right-skewed midline latent (`z²` up to ~16) through the `exp()` link blew up predicted rates, leaving `stat_covariate` far above the per-gene-mean floor (Fibroblast 435.6, Ambiguous 265.2; sometimes above its own init loss) with `p_value_covariate≈1.0`. IRLS solves the *same* model/objective to its MLE: post-fix Fibroblast 5.95, Ambiguous 17.33, each just **below** its intercept-only floor with correct nesting (quadratic ≤ linear ≤ floor). Assumption-neutral: predictor columns are standardized (invertible reparam, fit unchanged), degenerate genes use min-norm `pinv` (no ridge prior), all-zero genes get `λ=-20` (mean≈0). Gaussian linear/quadratic still OLS; `decoder="nn"` still GD (`train_isodepth_model`/`train_fixed_covariate_model` unchanged).
- **Covariate must not inherit `encoder="midline"`** (bug fix): the midline covariate is a FIXED `|x-median(x)|` baseline. The non-closed-form branch (nn decoder, or **Poisson which forces `closed_form=False`**) calls `train_isodepth_model(S, A, config)`. Because `train_batched_isodepth_model` checks `encoder_type=="midline"` BEFORE `_is_midline_covariate`, passing the main config (with `encoder="midline"`) built the covariate as a *learnable* `ParallelMidlineEncoderNet` that collapsed onto the main model (observed: `corr(true_isodepth, true_isodepth_covariate)=1.0`, `stat_true==stat_covariate`). Fix: that branch now passes `replace(config, encoder="mlp")` so the fixed-midline `HybridMidlineParallelNet` is built. Gaussian+linear/quadratic was unaffected (closed-form path returns `midline_latent(S)` directly); the bug only surfaced for Poisson, or `decoder="nn"`, combined with `encoder="midline"`.

## `encoder="midline"` (learnable 2-param straight line) — interpreting the isodepth triptych
- With `encoder="midline"` every parallel slot (true + all perms) is a `ParallelParameterizedMidlineEncoder`: a learnable straight line with only `θ`,`c` (`depth=|x·sinθ + y·cosθ − c|`, z-scored), **all slots initialized at `θ=0, c=0`** → the init axis is `|y|` (since `θ=0 ⇒ proj=y`).
- **The isodepth panels visualize only the encoder axis `(θ,c)`, NOT decoder fit quality.** Two slots with the same `θ` render identical pictures regardless of expression fit.
- **"True and null midlines look identical" is expected, not a bug**, when the real dominant gradient happens to align with the init axis. Hypothalamus `merfish_hypothalamus_rctd` case: true axis best-matches `θ=0.06 rad` (3.5° off init), `|corr(true_isodepth, |y|_init)|=0.80` vs `|x|=0.11`. The true model barely rotates from init; permuted slots have a flat-in-θ loss (no expr↔coord signal) so they never leave init → same `|y|` axis → identical panels. Rotating data 90° (or init `θ=π/2`) would make true vs null panels differ.
- **The real vs null difference lives in the DECODER, not the axis.** Along the (shared) `|y|` axis, real expression explains ~2.0% of variance vs ~0.04% (≈2/N chance) for shuffled — that gap is the whole significance (z≈184, p=0.01). The permutation null is statistically valid but razor-thin (std≈44 on 1.16M) and over-powered: it tests "any smooth axis vs zero", so on real 2-D tissue essentially every orientation passes (perpendicular learned `|y|` AND fixed-midline `|x|` are both "significant"; even a random smooth GP axis explains 0.8–2%). It detects existence of spatial structure, not a privileged gradient direction. A smoothness-matched null (random straight-line orientations or RBF-GP axes, fit via `fit_closed_form_decoder`) would be the specific/confound-aware bar; not yet implemented.

## Why the permutation null histogram (`*_metric_distribution.png`) is razor-thin
- Mechanism, not a bug. Three compounding reasons the null std looks tiny vs the absolute NLL level:
  1. **Only coordinates `S` are permuted; expression `A` is fixed** (`_build_permuted_coordinate_batch`). With `standardize_expression`, per-gene variance=1 so the predict-the-mean MSE floor =1.0 for *every* permutation. ~99.6% of the loss is this fixed irreducible-variance floor that no shuffle changes; only the spuriously-explained sliver moves.
  2. **Tiny model capacity on a shuffle**: a single smooth 1-D isodepth → 960-gene decoder can only overfit chance structure once coords are scrambled (e.g. explains ~0.36% of variance, MSE 0.9964 vs 1.0). That fraction is an average over `N×G` residuals (further denoised by `n_reruns` best-of-k), so it concentrates to ~1e-4 relative.
  3. **`nll_gaussian_mse = (n_total/2)·log(2π·MSE)+n_total/2`** amplifies that: `std(NLL) ≈ (n_total/2)·relative_std(MSE)`. Verified on `cosmx_luad9r1_c0_neutrophil_topright_gaussian` (N=1592, G=960): n_total/2=764160, relative MSE spread 4.2e-4 → predicted std 325 ≈ observed 324; true MSE 0.9945 vs null-mean 0.9964, z≈4.6, p=0.01.
- The null is wide only when the model can fit shuffles differently AND the loss isn't dominated by a fixed variance floor (far fewer cells/genes, or a high-capacity encoder that overfits each shuffle — which both widens and lowers the null). The 1-D-axis test is intrinsically a low, stable bar ("any smooth axis vs zero").

## Recursive SVG detection (`experiments/recursive_svg.py`)
- Entry point: `run_recursive_svg(dataset, run_config)` — replaces `save_standardized_outputs` when `config.recursive=True`.
- SVG significance uses the parametric F-test (`_ftest_decoder_pvalues`) + BH correction; requires `decoder in {"linear","quadratic"}` (`decoder_df` = 1 or 2). **nn decoder is not supported and raises ValueError at schema validation time.**
- `compute_isodepth_sig_genes(A, gene_names, pred_isodepth, decoder_df, coord, alpha)` in `analysis/plots.py` is the reusable helper that returns `{sig_indices, sig_names, pvalues, qvalues}`.
- Dispatch: `run_config.data.cell_type_mode == "separate"` → `_run_recursive_svg_separate`; else → `_run_recursive_loop` directly.
- **Plain / together mode**: outputs go under `results/<run_name>/recursive/` — one `gradient_<k>/` folder per iteration plus `combined_sig_genes.csv` and `recursive_summary.json`.
- **Separate mode** (`_run_recursive_svg_separate`):
  1. Runs the full separate-mode permutation test once via `run_permutation_method`.
  2. Saves all standard per-type plots/CSVs via `_save_separate_celltype_outputs` (no behaviour change).
  3. For each cell type with `p_value < alpha`, builds a plain `DatasetBundle(S=type_data["S"], A=type_data["A"], meta={"var_names": ...})` and calls `_run_recursive_loop` into `<type_dir>/recursive/`.
  4. Writes `<type_dir>/recursive/recursive_summary.json` per type, and a top-level `<run_name>_celltype_recursive_summary.json`.
  5. `plain_config = replace(config, covariate=None)` strips the covariate for per-type recursive iterations (covariate is already handled in the initial run).
- `cell_type="none"`, `"together"`, and `"separate"` are all supported. The `"separate"` mode check uses `run_config.data.cell_type_mode`, not `dataset.meta["cell_type_mode"]`.

## Existence test is decoder-capacity-sensitive (overfitting hazard)
- **Finding (CosMx neutrophil blob `cosmx_luad9r1_c0_neutrophil_topright`)**: with `decoder="nn"` the existence test gave an *odd, left-skewed, jagged* Poisson null where several permutations beat the true coord (p≈0.09–0.11, z≈0.9–1.6); raising epochs 500→1500 + cosine decay made it **worse** (longer left tail, lowest null 0.7022→0.7012). Switching to `decoder="quadratic"` (same data/metric) gave a clean symmetric null (std 2.5e-4→4e-6), true centered (33/99 below), **p=0.34** → no gradient.
- **Why**: the test statistic is *in-sample training reconstruction loss* (best-of-`n_reruns`). A flexible NN can carve a low-loss smooth axis out of noise on **any** coordinates incl. shuffled, so more training overfits each permutation better and the null is overfitting-variance-dominated (not optimization failure). A quadratic decoder can't bend to noise → all coord arrangements score ~equally → calibrated null. The optimizer is fine; in-sample loss + high capacity is the wrong objective for a calibrated test near the null.
- **Correct interpretation (do not overstate)**: the NN-Poisson runs were **non-significant** (p≈0.09–0.11), the SAME conclusion as quadratic (p=0.34) — the NN did NOT false-positive on depth-corrected data; the jagged null was a *precision/power* artifact, not a flipped verdict. The Gaussian NN *fire* (p=0.01) was the NN fitting **real** structure (the depth/density confound), not hallucinating noise. So NN flexibility is desirable (a real hypoxia-type gradient is nonlinear; quadratic-only would lose power → false negatives).
- **Root cause is the statistic, not NN capacity**: using *in-sample training loss* (best-of-`n_reruns`) makes a flexible model's null heavy-tailed/capacity-sensitive and costs power. **Preferred fix that keeps NN flexibility: held-out `method: cross_validation`** — a true (even nonlinear) gradient generalizes to held-out cells (stays significant); noise overfit doesn't (null tightens, centered). Constraining the decoder (linear/quadratic) is a cheaper capacity-limiting diagnostic, not the production choice. Decoder = the gradient *family* claimed, so fix it a priori (NN primary + linear/quadratic as secondary "is it simple/monotone?"), don't pick after seeing p.

## Library-size normalization & Poisson offset (depth confound)
- **Why**: with no per-cell depth normalization, `X=log1p(counts)` leaks library size into every gene coherently; if depth drifts smoothly in space the existence test fits it as a fake gradient. LUSC-6 tumor-interior crop fired at z~70 purely from this (PC1↔depth corr 0.91).
- `data/transforms.py::normalize_total_expression(a)` — per-cell CPM normalization (`a_ig / N_i * 10^6`; with `log1p` → standard log-CPM `log(a_ig / N_i * 10^6 + 1)`). Runs **before** `log1p`, Gaussian path only. Wired as `DataConfig.normalize_total` / CLI `--normalize-total` / `--no-normalize-total`, and recorded in dataset meta. Mutually exclusive with `q` (schema + transform guards) and h5ad-only. Target sum is fixed at `1e6` (not configurable).
- `poisson_low_rank_factorization` now fits `log E[Y]=log s_i + beta_g + L R^T` with **size-factor offset** (`size_factor_offset`, total counts as exposure — same as RCTD/C-SIDE) and learnable **per-gene intercept** (`gene_intercept`), both default `True`. Without them the leading latent factor is just library size.
- **GASTON correspondence**: GASTON's recommended pipeline is Poisson **GLM-PCA** (`fam="poi"`) on UMI counts -> z-score factors -> NN with **MSE/Gaussian** loss (it does *not* log-normalize, and does *not* use a Poisson loss in the NN). That maps onto: `q` (`poisson_low_rank_factorization` == GLM-PCA) + `standardize_expression` + `nll_gaussian_mse`. The offset+intercept added here is what makes `q` a faithful GLM-PCA (previously its top factor was library size). So the GASTON-native depth handling is the `q`/GLM-PCA path, NOT `normalize_total` — keep `normalize_total` optional/default-false (Gaussian-path-only convenience knob).
- **Empirical finding (important)**: neither remedy fully sterilizes the LUSC-6 low-count crop. `normalize_total`+log1p drops PC1↔depth corr 0.91→0.41 but the crop stays p=0.01 (z~97); Poisson offset drops PC1↔depth 0.84→0.47 but leading factor still ~0.57. Only **explicit residualization on log-depth** collapses PC1 spatial R² (0.116→0.029). Reason: in low-count imaging data the depth→log-expression coupling is **nonlinear (dropout)**, and the plain Poisson lacks overdispersion so its latent re-absorbs depth. There is also a secondary **cell-density** gradient (spatial R²~0.42, corr 0.38 with PC1). Robust depth removal needs explicit depth conditioning (covariate `n_counts`, a depth-residualization preprocessing step, or an NB/overdispersed Poisson) — not normalization alone.
- **Head-to-head on LUSC-6 crop (effect size z = (null_mean - stat_true)/null_std, n_perms=99, p floor 0.01)**: pre-logged-X Gaussian z~70; `normalize_total`+log1p Gaussian z~97; **`nll_poisson_mse` (raw counts, `standardize_expression=false`, `log1p=false`, library-size row-sum as fixed exposure) z=8.3** — i.e. the Poisson exposure removes ~90% of the spurious effect but the crop stays significant. Poisson config: `configs/cosmx_lusc6_fov23_tumor_interior_poisson.json`. Residual z~8 is not depth (exposure handles that); likely the **cell-density spatial gradient** (R²~0.42, not addressed by per-cell exposure), Poisson overdispersion (needs NB), and/or subtle real tumor biology. Conclusion: Poisson is the right default for depth, but is NOT a complete negative-control fix on its own.

## Labeled-covariate comparison: drop a per-cell axis label into `test.covariate` and race it vs the learned isodepth
- Mechanism (already wired): set `test.covariate` to an **obs-column name** (string). Loader (`data/h5ad_loader.py`) reads `adata.obs[key]`, z-scores it (`zscore_covariate`), fits a **decoder-only** model on that FIXED axis, and reports `true_isodepth_covariate`, `stat_covariate`, `p_value_covariate`, plus `*_residual_ratio_*` (`RSS_covariate/RSS_fitted`, >1 ⇒ learned coordinate wins). `run_permutation.py` passes `covariate=run_config.test.covariate` to `load_dataset`. (Midline geometric covariate is the special `"midline"` string; any other string = obs key.)
- Interesting readouts per run: `|Spearman(isodepth, covariate)|` (does the unsupervised axis recover the known one) and the residual ratio (does the continuous isodepth BEAT the coarse/curved label).
- Datasets with a labeled axis: liver `dist_central`, DLPFC layer ordinal, hypothalamus `midline`, **STARmap cortex `cortical_depth`** (below).

## Covariate-recovery sweep (async on SLURM)
- `scripts/covariate_recovery_sweep.py`: runs every labeled-covariate config (all `configs/stmliver_*.json` + `configs/starmap_mvc_BY3.json`) and writes `results/covariate_recovery/summary.{csv,png}` (per run: `p_value`, `|Spearman(isodepth, covariate)|`, `stat_true` vs `stat_covariate`, `learned_beats_label`, residual-ratio summary). Modes: default = run all + summarize; `--summarize` = only rebuild summary from existing `results/<run_name>/` dirs; `--config A B` = run subset.
- **Async on the cluster**: `run_covariate_sweep.sh` is a SLURM **job array** (`--array=0-12`, one a100 GPU task per config; header copied from `run_config.sh`, time 2h). `run_covariate_summary.sh` runs `--summarize` (same a100 header). `submit_covariate_sweep.sh` submits the array + a `--dependency=afterok` summary in one shot. The array index → config list must stay in sync (12 `stmliver_*` sorted + starmap = 13 ⇒ `--array=0-12`).
- **Early finding (full runs)**: STARmap cortex recovers `cortical_depth` at `|rho|≈0.98`; liver section-level recovery of `dist_central` is mostly LOW (0.02–0.17) **because `dist_central` is multimodal at section scale** (distance to *nearest* central vein → many wells; a single isodepth can't track it). Exception: `CN65_C1` (no central vein in-frame ⇒ monotone label) recovers at `|rho|=0.65`. Lesson: the labeled-covariate comparison is well-posed only when the label is a **single monotone axis** (cortex depth, hypothalamus midline); multi-well fields need the per-lobule framing instead.
- **Gotcha**: files created by the editor here are sometimes `root`-owned and non-executable; `sbatch script.sh` works regardless (sbatch reads the file), but `./script.sh` may not — use `bash script.sh` or `sbatch`.
- **Caveat on the STARmap covariate**: `cortical_depth` (layer ordinal) is ~a 6-step staircase along x (`corr=-0.98`), so feeding it as a covariate is degenerate (≈ binned-x); learned isodepth "beating" it just means continuous>quantized. The non-degenerate liver covariate (`dist_central`, multi-vein geometry) is the meaningful one. **Why covariate beat learned in several liver sections (z_cov>z_true, e.g. CN65_C1 6.4→10.7)**: not a capacity issue (encoder *could* output `dist_central`) — it's inductive bias + mis-specification. `dist_central` is a high-frequency multi-well field (resets at each of ~20 veins); the smooth MLP encoder is biased to one low-frequency monotone axis and can't synthesize the multi-well field, while the covariate is handed it (plus it carries privileged vein-mask info). GASTON's single-monotone-isodepth premise is violated by whole-section liver (periodic across lobules) → right unit is the lobule. STARmap (single monotone axis) → learned wins (z 56>40), confirming the diagnosis.

## DLPFC Layer 3 warm-start vs cold-start Poisson (Phase 2) — non-convexity probe
- Question: warm-start a Poisson isodepth model AT the frozen Gaussian axis and let it train freely — does it stay near Gaussian or collapse to the cold-start solution? Script: `scripts/dlpfc_layer3_poisson_warmstart.py` (reuses the Phase-1 spec `configs/experiments/dlpfc_layer3_gaussian_axis_poisson.json` for data/prep). Outputs `results/dlpfc_new/layer3_poisson_warmstart/{*_loss_curves.png, *_summary.json/csv}`.
- Three trainings, ALL under the same **Poisson NLL**, all from epoch 0, each `n_reruns` parallel inits sharing one seed (only A's frozen encoder / B's warm start differ): **A** = frozen Gaussian axis (decoder-only on exact z-scored axis), **B** = warm-start (encoder pretrained to axis via MSE-regression + decoder copied from A, then full model free), **C** = cold-start (default init, full model free). Self-contained full-batch Adam loop in the script (reuses `ParallelIsoDepthNet` + `_compute_reconstruction_loss_per_model`); does NOT go through `train_batched_isodepth_model` (whose `record_loss_history` only logs slot 0). Plot: each experiment's reruns in grey, best (lowest final-loss) rerun dark; log-y panels + a converged-tail overlay.
- **Result (epochs=1500, n_reruns=10)**: encoder regresses the Gaussian axis at |corr|=0.998 (axis IS MLP-representable — it was produced by the same 2→20→20→1 MLP). Final Poisson NLL **warm=1.0411 < cold=1.0475 < frozen-exact=1.0562**. Converged axis |Spearman|: **warm-vs-gauss=0.83, cold-vs-gauss=0.13, warm-vs-cold=0.11**.
- **Interpretation**: the Poisson objective is non-convex with a distinct basin **near the Gaussian axis that is BETTER (lower NLL) than where cold-start lands**. Cold Poisson training converges to a different, worse axis essentially uncorrelated with Gaussian (|ρ|=0.13). Warm-start stays near Gaussian (doesn't run away; |ρ|=0.83) and slightly refines below the frozen-exact floor (1.056→1.041, encoder moving a hair improves the decoder fit). So Gaussian is a good Poisson optimum that cold Poisson SGD fails to find — a basin/initialization problem, not that the Gaussian axis is wrong for Poisson.
- Caveat: full-batch Adam here (not the SGD-128 of the permutation config) for smooth comparable curves; convergence behavior is representative but absolute epoch counts aren't comparable to the SGD runs.

- **KEY FINDING (raw vs log-CPM Gaussian phase, E10.5 Heart, n=728)**: training the Gaussian/MSE phase on **raw counts** makes `gaussian_free`/`gaussian_frozen` blow up monotonically with m (m=500 → NLL ~1e22), because MSE-on-raw-counts produces a huge-magnitude unscaled axis. ## Cross-validation (`test.method = cross_validation`)
- Uses deterministic shuffled k-fold splits (`test.n_folds`, default 5) instead of `train_fraction`.
- Folds run **sequentially**; within each fold the true + `n_perms` permuted models still train in parallel with shared train/test masks.

- Metrics: `mse`, `nll_gaussian_mse`, `nll_poisson_mse` (masked Poisson NLL on holdout cells).

## Synthetic spatially correlated noise kernel (`data.kernel`)

- Model: `Σ = σ²(I + δ·K)` where `K_ij = exp(-d_ij / p)` and `d_ij` is Euclidean distance in microns.
- Config fields on `DataConfig`: `scale` (tissue width in µm, maps unit-square → µm), `kernel: {type, distance, max_interaction_distance}`, `delta` (float ≥ 0).
- `delta = 0` → IID noise (no local autocorrelation, current default behavior).
- Local fraction = `δ/(1+δ)` — fraction of per-cell noise variance that is spatially correlated.
- `kernel.effective_cutoff` defaults to `4 × distance` (K < 2% there); set `max_interaction_distance` to override.
- Implementation: `SpatialDataSimulator._build_cholesky()` uses `scipy.spatial.KDTree.query_pairs(r_max)` to build sparse K, then dense Cholesky on `C = I + δK`. Called lazily and cached. Works for both Gaussian and Poisson expression distributions (adds noise to `log_rate` for Poisson).
- **N scaling**: Cholesky is O(N³). Fine up to N≈2500; for larger N add sparse Cholesky backend (`scikit-sparse`) or keep N small.
- Kernel diagnostic plot (`*_kernel_diagnostics.png`): Panel 1 = correlation curve `corr(r)` vs. r in µm; Panel 2 = single gene noise draw on the spatial grid. Generated automatically by `save_standardized_outputs` when `data.kernel` is set.
- **`coordinate_um_per_unit`** in block_permutation configs for the unit-square synthetic data: set to `scale` (e.g. 2000.0 if scale=2000) since 1 unit = 2000 µm.
- Configs: `configs/synthetic/kernel_delta{0,1,4}_radial.json` (radial gradient + varying local fraction), `kernel_delta4_noise.json` (pure local structure, no gradient — critical negative control for block permutation).
- **Kernel-noise sweep** (`configs/experiments/kernel_noise_study.json`): grid over ρ∈{5,15,30} µm, δ∈{0.01,0.05,0.1}, 10 data seeds; caches each synthetic dataset once (`results/experiments/kernel_noise_study/datasets/`), runs coordinate perm then block perm at r∈{15,30,60} µm on the same cache. SLURM: `sbatch --export=ALL,CONFIG=configs/experiments/kernel_noise_study.json run_config.sh`. Summary plot: `analysis/kernel_noise_study_pvalue_comparison.png` (3×3 δ×ρ panels, coord vs block p-values across seeds).
